# 项目路线图

本文档用于记录“国产化OA集成项目管理系统”的总体方向、近期优先级和待办功能。日常开发遵循“主窗口决策、功能窗口实施”的方式。

## 当前版本状态

- 当前主分支：`master`
- 当前稳定功能版本：`gantt-optimization-20260623`
- 当前阶段：本机可用、局域网分享、持续增强项目治理和智能分析能力
- 当前重点：提升 Wiki 来源治理、智能问答质量、文档权威体系、项目管理视图可读性

## 近期优先级

1. Wiki 来源治理和全系统事实来源统一
   - 确保首页、Wiki、智能问答、里程碑、任务、交付物使用统一来源规则。
   - 合同、需求、招投标、正式变更等高权威资料优先进入项目基线。
   - 周报和会议纪要主要用于当前进度、风险、会议决议和待协调事项。

2. 智能问答质量优化
   - 优先基于 Wiki 和项目计划基线回答。
   - 回答必须带来源、权威标签和可点击预览。
   - 避免只召回会议纪要导致答案偏过程化。

3. OCR 与项目 Wiki 稳定性增强
   - 图片版 PDF OCR 后台化、可重试、可查看失败原因。
   - Wiki 更新建议后台生成，并展示进度和失败原因。
   - Wiki 正式内容必须由管理员确认后写入。

4. 版本发布与迁移体验
   - README 面向使用者保持简洁。
   - `docs/CHANGELOG.md` 记录稳定版本、提交号、tag 和回退方式。
   - 分享给其他人前，确保启动、迁移、数据目录配置说明清晰。

## 待办池

- 系统内所有更新类按钮继续统一 loading 状态和进度反馈。
- 智能建议、Wiki 建议、权威建议的批量应用结果要显示成功和失败明细。
- 文档权威台账需要继续增强人工治理体验。
- 智能问答可增加“引用范围”提示，例如合同依据、计划基线、过程资料。
- 增加稳定版本发布检查清单，避免功能完成后忘记 tag 或更新日志。

## 暂缓事项

- 第一版不引入 GitHub Issues / Projects。
- 第一版不引入外部 RAGFlow、向量数据库、Redis、Celery。
- 第一版不做复杂多角色权限，只保留普通用户和管理员。
