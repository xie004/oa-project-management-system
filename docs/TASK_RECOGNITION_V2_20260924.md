# 任务识别 V2（准确优先）

## 识别口径

- 周报和会议资料先按章节、段落、表格行识别完整事项，再统一进入候选池。
- “本周进展”识别为进度证据；“下周计划、会议决议”识别为计划候选。
- 页码、页眉页脚、表头、纯说明和无法在原文定位的模型结果会被过滤。
- 每项保留原文、位置、批次、规则版本和过滤原因；责任人、日期未出现时保持为空。
- 模型按全文批次处理，不再静默截断前 8～12 项；失败批次标为部分失败并允许后续重试。

## 匹配与写入

- 扫描、智能建议、识别事项、数据治理和进度重算共用任务匹配规则。
- 匹配维度包含工作对象、动作、批次和阶段；批次或环境不一致时不得自动关联。
- 匹配分不低于 90%、目标唯一且范围一致时，只追加来源证据；正式字段变化仍生成待确认建议。
- 未匹配的进度描述不会创建新任务；明确的新计划才进入待确认建议。
- 普通完成事项不再生成里程碑。

## 历史试算

管理员可在“任务看板 → 识别质量历史试算”运行最近三期周报及同期会议纪要试算。

- 接口：`POST /api/tasks/recognition-preview`
- 状态：`GET /api/tasks/recognition-preview-status`
- 结果：`GET /api/tasks/recognition-preview-results`
- 结果分为：疑似新增、重复/应聚合、疑似误识别、匹配变化、进度变化、处理失败。
- 试算只写入独立的试算结果表，不修改正式任务、来源证据和 Wiki。

## 回退与验证

- 实施前回退标记：`before-recognition-accuracy-20260924-131210`
- 数据备份：`rollback-backups/recognition-20260924-131210`
- 隔离副本试算确认：正式任务、来源证据和 Wiki 摘要在试算前后保持一致。
